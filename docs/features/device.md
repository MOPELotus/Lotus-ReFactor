# 设备信息-profile 绑定

返回：[上一级](../profile-login.md) / [文档目录](../README.md) / [小功能索引](README.md)

## 功能特性

- 每个 profile 独立保存设备信息，不会和其他 profile 共用或覆盖。
- 米游社社区签到、游戏签到 UA、绝区零更新面板等请求会自动使用对应 profile 的设备字段。
- 支持完整设备 JSON，也支持已有的 `device_id/device_fp`。
- 资料卡和设备信息页只展示脱敏内容。

设备 ID 和 FP 必须来自同一设备；只有 FP、没有对应 ID 的新绑定会被拒绝。更换设备时，不沿用旧设备的名称、型号等信息。绑定保存后会同步既有上游绑定及设备缓存；同步失败保留待修复标记，后续重试同步，不重复兑换登录凭据。

荷花桥接的请求明确携带 profile 上下文。公共请求层还会处理 genshin、Miao 和 ZZZ 使用的米游社请求：核对实际 Cookie 所属账号，再选择对应的设备 ID、FP 和可用设备字段。共享 CK 使用实际 CK 所属账号的信息；同账号多个 profile 有不同设备时，不能仅凭账号 UID 选择第一个 profile。没有设备信息的 profile 自动生成并保存虚拟设备，后续请求复用其 ID、型号和系统信息；不在每次请求时重新随机。已有完整或部分设备信息保留，避免静默替换用户提供的身份。

请求、验证码创建、业务校验与重请求沿用同一设备上下文。`mys.req.err` 负责错误后的处理，不能替代发请求前的设备核对。Passport、米游社记录、社区、商城和云游戏按各自协议生成签名及请求字段，不将一套请求头套到全部接口。

## 自动设备

新 profile 创建时保存随机虚拟设备；旧档案在启动时补齐。型号、Android/API 版本、固件指纹、屏幕和容量从相容组合选取，当前覆盖 Pixel 6 至 Pixel 8 系列及 Android 12–14。完整固件指纹参考 [Google 官方透明日志](https://developers.google.com/android/binary_transparency/image_info.txt)，身份标识随机生成并固定保存。

FP 仅接受官方成功签发的结果。插件启动后延迟补全，使用已经保存的设备 ID；失败时保留原设备、不发送假 FP，并按退避间隔重试。已有 FP 的设备不重复申请。ID 与 FP 齐全后可运行已开启的社区任务；补全前仅跳过需要完整设备信息的任务。

绑定真机后覆盖自动设备信息。正在进行的后台签发会核对设备实例和登录状态，旧结果不能覆盖新绑定；自动生成不会更改签到开关。

## 指令用法

```text
#绑定设备[profile]
#绑定设备信息[profile] <设备信息>
#原神绑定设备[profile]
#星铁绑定设备[profile]
#绝区零绑定设备[profile]
#设备信息[profile]
```

## 变量说明

- `profile`：可选，Lotus 内部 profile 序号，范围 `1..255`；省略时使用 profile 1。
- `设备信息`：可选，完整设备 JSON 或包含 `device_id/device_fp` 的文本。省略时按交互提示继续绑定。
