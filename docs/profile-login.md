# 登录与多 profile

返回：[项目主页](../README.md) / [文档目录](README.md)

一个 QQ 最多允许 `1..255` 个 Lotus profile。

- `#扫码登录` 绑定 profile 1。
- `#扫码登录2` 绑定 profile 2。
- `#刷新cookie` 刷新当前 QQ 的全部 profile。
- `#刷新cookie2` 只刷新 profile 2。
- `#登录列表` 查看已创建 profile。
- `#清除登录2` 清除 profile 2 的敏感登录信息。

profile 只是 Lotus 内部槽位，不等于米哈游 `ltuid`，也不等于游戏 UID。

登录成功后，荷花插件会保存：

- cookie
- stoken
- mid
- ltoken
- 米哈游角色列表
- genshin/miao 能识别的 NoteUser/MysUser 关系

账号密码登录已经裁剪。外部插件的账号密码入口会被荷花插件阻断，并提示改用扫码登录。

## 配置资料卡

发送：

```text
#荷花配置
#荷花配置2
```

资料卡会显示登录态、设备、角色、签到开关和通知设置。敏感字段会脱敏。

## 旧登录格式自动修复

本分支在插件启动 30 秒后自动扫描全部 profile，检测令牌放错 v1/v2 Cookie 字段、缺少相应 UID/MID、各处账号 UID 冲突或保存的 ltoken 不一致。发现问题后，用该 profile 的 stoken 同时重新获取 ltoken 和 cookie_token，成功后再保存；正常的旧版 Cookie 不会仅因版本旧而刷新。失败项每 6 小时复查，也可使用 `#刷新cookie` 手动重试。

扫码登录、手动刷新和自动修复共用同一套凭据生成逻辑。字段取决于接口实际返回的令牌：v1 与 v2 可以合法并存，不因 stoken 是 v2 就将所有 Cookie 强行写成 v2。刷新会核对返回账号，保留 profile 设置；接口失败或登录被更换时不覆盖原凭据，保存使用同目录临时文件原子替换。UID 会从账户字段、Cookie 和 stoken Cookie 的各个别名中核对；可信 stuid 相互冲突时保留原值并要求重新登录，不猜测账号归属。扫码保存或刷新进行期间清除登录，会使较旧操作失效；多个扫码结果交叠时，以较新开始保存的结果为准，网络请求不会占用账户写入锁。

自动修复也会同步 genshin 已加载的 Cookie 缓存。待同步状态仅保存 profile 标识，不保存令牌；同步失败后即使重启，也只补同步而不重复刷新凭据。启动时还会核对既有绑定的缓存差异，不为原本未桥接的正常账户新增绑定。扫描遇到损坏的 profile 文件会单独跳过，继续处理其他账户。

设备变更同样参与缓存同步和并发检查；不能只比较 Cookie 是否相同。明确指定 profile 的请求会把该上下文传到验证码和过期凭据刷新，避免同账号的另一个 profile 被误刷新。没有明确 profile 的外部请求，必须结合实际凭据和设备确认归属；无法唯一确认时，不自动刷新某个碰巧匹配 UID 的档案。

## 扫码会话与凭据交换

二维码创建、确认轮询和扫码后的凭据交换使用同一个客户端会话。已有 profile 使用自己的设备 ID、FP 和设备资料；新 profile 先保存自己的虚拟设备，再用该设备创建独立会话；未取得与该 ID 配对的 FP 时省略 FP，不使用共享固定值。刷新多个 profile 时分别创建客户端，避免设备信息串用。

v2 stoken 的凭据交换使用 Passport 接口，携带该会话的设备信息、stoken/MID Cookie 和对应签名；v1 stoken 保留旧接口兼容。HTTP 410 不会触发盲目切换 POST 或重复交换。接口失败、返回账号 UID/MID 不符时保留原凭据，只有完整取得并核对令牌后才保存。
